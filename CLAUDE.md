# design-payment-system

Learning project that builds a payment system, step by step.

## Writing style

Write in simple English. The reader speaks English as a second language.

Follow the `plain-english` skill in `.claude/skills/plain-english/SKILL.md` for
every reply, document, comment, and commit message. Read it now if you have not.

The short version:

- Short sentences. One idea per sentence. 20 words or fewer.
- Common words. Write "use", not "leverage".
- Active voice. Name who does the thing.
- **No phrasal verbs.** Write "start the container", not "spin up the
  container". These are the hardest part of English for a non-native speaker,
  because the meaning does not follow from the two words.
- No literary flourishes. State the point.
- Use tables, lists, and code blocks. Structure helps more than prose.

Keep all software engineering terms exactly as they are: idempotent, outbox
pattern, consumer group, DLQ, transaction, connection pool, at-least-once
delivery. The reader is a software engineer and knows these words. Replacing
them loses precision.
